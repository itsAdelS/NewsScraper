Add a secure, internal-only admin console to the existing PayerNews Scraper application.

* GET /health

Goal

Create a secure admin area accessible at:

/admin

Users who are not authenticated must be redirected to:

/admin/login

The admin console is intended for a scraper administrator to:

* monitor scraper health
* monitor Playwright/browser pool utilization
* review recent API requests
* review successes and failures
* inspect scraper performance
* see queue pressure
* pause/resume incoming scrape work if needed
* diagnose problems without reading raw server logs

The admin console must not be publicly accessible without authentication.

⸻

Authentication

Implement a proper login page for the admin area.

Route:

GET /admin/login

The page should contain:

* Username
* Password
* Sign In button
* Clear invalid-login message
* Simple professional styling matching the scraper application

For the initial implementation, credentials may be configured using environment variables / Replit Secrets.

Use:

ADMIN_USERNAME
ADMIN_PASSWORD_HASH
SESSION_SECRET

Do not store the plaintext password in source code.

Prefer storing a securely hashed password rather than a plaintext password environment variable.

Use an established password hashing library such as bcrypt or Argon2.

Do not log passwords.

Do not return passwords through any API.

⸻

Session Security

Use secure server-side or signed cookie-based sessions.

Authentication should work like:

/admin/login
      ↓
Successful authentication
      ↓
Create authenticated session
      ↓
Redirect to /admin

The authenticated session should protect all routes under:

/admin/*

except:

/admin/login

Add:

POST /admin/logout

Logout should invalidate the current session and redirect back to /admin/login.

Configure cookies with appropriate security settings such as:

* HttpOnly
* SameSite=Lax or stricter
* Secure when running over HTTPS

Sessions should expire after a reasonable period of inactivity.

Suggested initial timeout:

8 hours

Make this configurable.

⸻

Brute Force Protection

Protect the admin login against repeated password attempts.

Implement basic rate limiting such as:

* Maximum 5 failed attempts within 15 minutes per IP
* Temporarily reject further attempts during the lockout period

Do not reveal whether the username or password was incorrect.

Use a generic message such as:

Invalid username or password.

Admin Controls

Add an administrative controls section.

At minimum:

Pause New Scrape Requests

Allow the administrator to temporarily prevent new scrape jobs from being accepted.

When paused, /api/scrape should return a controlled response such as HTTP 503:

{
  "success": false,
  "status": "paused",
  "error": "Scraping is temporarily paused by administrator.",
  "retryAfterSeconds": 300
}

Important:

Existing active or queued jobs should continue processing.

This action should stop only new incoming scrape requests.

Resume Scraping

Allow the administrator to resume accepting new requests.

Drain Mode

If practical, implement a drain mode:

Stop accepting new jobs
Continue processing currently queued/active jobs

Clearly distinguish this from deleting queued jobs.

⸻

Do Not Add a Destructive Flush Yet

Do not initially create a button that deletes all queued scrape jobs.

I want queue draining rather than silently discarding valid Power Automate requests.

A destructive flush mechanism can be considered later if necessary.

⸻

Control Safety

Administrative actions such as Pause, Resume, or Drain must:

* require authentication
* use POST requests
* include CSRF protection or an equivalent safety mechanism
* require an intentional button click
* display the resulting state clearly

Do not make state-changing admin controls accessible via GET requests.
